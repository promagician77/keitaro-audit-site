    Read-only tracker audit

    A Node script reads the tracker through the Admin API and checks it against 37 rules taken from Keitaro's documentation. It sends GET requests only. Report queries are opt-in. Below is its output on a sample tracker with planted problems and one clean campaign.

    How Keitaro picks a flow, and where that goes wrong

    1. Forced flows are checked first, top to bottom. The bot flow belongs here.
    2. Regular flows come next. With split-testing off they're checked top to bottom; with it on, at random by weight.
    3. The Default flow takes whatever is left. With no Default flow, the click gets Do Nothing.

    Sample tracker, campaign “DE Sweeps”

    • RegularMain offerno filterstakes every click, bots included
    • RegularBotsBot ISnever reached
    • RegularAustriaCountry IS ATnever reached
    • DefaultDefault

    Fix: make “Bots” a Forced flow and give “Main offer” its filters, or move it down. Findings F03 and F04 below.

    Run it on your tracker

    Two ways, both read-only. The key comes from Maintenance → Users → Admin API keys and stays in your shell.

    Make a redacted snapshot and send me the JSON (tokens, postback keys and URL values removed):

    KEITARO_API_KEY=your_key node audit/keitaro-audit.mjs --url https://your-tracker --snapshot-only --out audit-out

    Or run the full audit yourself; add --with-reports for 7 days of bot share per source:

    KEITARO_API_KEY=your_key node audit/keitaro-audit.mjs --url https://your-tracker --out audit-out

    Filtering playbook

    What I set up after the audit, in this order.

    1. One Forced bot flow on top

      Bot filter IS, the same landing page people get, no offer attached, Collect clicks on. Ad reviewers see the page people see; bot clicks just never reach the network, and bot share stays measurable per source.

    2. Feed the Bot filter your own data

      Paste the analyzer's data-center prefixes into Settings → Bot lists, where the Bot filter reads them, and turn on the built-in lists and “empty user agent as bot”.

    3. Check what the Proxy and ISP filters can see

      The Proxy filter reads headers unless IP2Location PX2 is loaded. The ISP filter needs Keitaro Geo or DB4. Without them both filters can show as on while matching nothing.

    4. Regular flows with filters, one Default

      No unfiltered regular flow above others, no OR across IS NOT conditions, and one Default flow so nothing falls into Do Nothing.

    5. Block placements at the source

      Zones with a high bot share go on the source's blacklist, with the click list (subid, IP, user agent, reason) as refund evidence.

    6. Re-run weekly

      Export clicks, run the analyzer, compare bot share by source. New data-center ranges go into the bot list; flood IPs expire after a week.
